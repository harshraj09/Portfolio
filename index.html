The Challenge

Building an LMS that works across different users, roles, and workflows.

Collegese LMS was built as a full-stack learning platform for managing courses, students, teachers, assessments, progress, and administrative workflows. The challenge was not just creating individual screens, but turning a complex set of workflows into a responsive and usable web application.

"The goal was to turn a complex learning workflow into an interface that feels structured, responsive, and easy to navigate."

01
The Vision
The Problem

Remote collaboration needed more than another communication tool.

Traditional remote collaboration tools mainly focus on calls, messages, and meetings. We explored a different approach: creating a shared virtual environment where users could experience presence, movement, and interaction together.

"Instead of another window for communication, we wanted to build a shared digital space where people could actually interact."

02
The Build
Engineering the Experience

Turning a virtual workspace concept into a real-time application.

  • Real-Time Presence: Implemented real-time avatar movement and shared application state using Socket.io so users could see activity happening inside the virtual workspace.
  • Peer-to-Peer Communication: Integrated WebRTC to enable direct communication between users inside the virtual environment.
  • React + TypeScript: Built the application interface with React.js and TypeScript, keeping the frontend structured and scalable.
  • Persistent Application Data: Integrated Firebase to maintain application data and support a consistent experience across sessions.
  • Authentication: Implemented authentication flows to provide controlled access to the virtual workspace.
03
The Experience
Real-Time Interaction

The interface was only the beginning — the environment had to respond.

The core challenge was making the virtual environment feel alive. User movement, presence, and communication needed to happen in real time rather than behaving like a collection of static screens.

Avatar Movement

Users can move their avatars around the shared virtual workspace while their presence is reflected for other users.

Live Communication

WebRTC enables peer-to-peer communication between users inside the virtual environment.

Real-Time Events

Socket.io handles real-time communication between connected clients and keeps interactions synchronized.

Persistent Data

Firebase provides persistent application data so the experience isn't limited to a single temporary session.

04
The Engineering
Technical Decisions

Choosing technology around the experience, not the other way around.

  • Socket.io was used for real-time events and synchronization between connected users.
  • WebRTC enabled peer-to-peer communication without routing the entire communication flow through the application server.
  • TypeScript added stronger type safety and structure to a frontend handling complex interactive state.
  • Firebase was used for persistent application data and supporting the application's connected experience.
05
The Outcome
Recognition

Best Project of the Year — CreateX.

The project was presented at the CreateX Inter-College Tech Event and received recognition as Best Project of the Year. The experience gave me hands-on exposure to building a real-time application where frontend development, networking, communication, authentication, and persistent data all had to work together.

01
The Problem
Data Challenge

Pollution data is powerful — but difficult to understand when it stays buried in numbers.

Delhi-NCR generates large amounts of air-quality data across different pollutants and time periods. Looking at individual measurements makes it difficult to identify broader pollution patterns, understand source-related behaviour, or anticipate how AQI may change over time.

"The goal wasn't just to display pollution data. It was to turn historical data into something people could explore, compare, and understand."

02
The Data
Five Years of Delhi-NCR Data

From historical pollution records to meaningful patterns.

The project analyses five years of Delhi-NCR pollution data to uncover trends and relationships across air-quality measurements. The dashboard brings those patterns together into an interactive visual experience.

  • Historical pollution trends across the available five-year dataset
  • Comparative analysis of pollution-related parameters
  • Visual exploration of changing air-quality patterns
  • Source-related insights derived from the analysed data
03
The Forecast
AQI Forecasting

Moving from what happened to what could happen next.

The forecasting component uses the historical pollution data to identify AQI trends and provide forecast information. Instead of limiting the dashboard to historical reporting, the project introduces a forward-looking view of air-quality behaviour.

Historical Analysis

Explore five years of Delhi-NCR pollution data and identify long-term patterns.

Pollution Insights

Surface patterns and source-related information through interactive visualizations.

AQI Forecasting

Use historical trends to provide a forward-looking view of AQI behaviour.

Interactive Dashboard

Present complex environmental data through visualizations designed for easier exploration.

04
The Dashboard
Visualization

Making environmental data easier to see.

The dashboard acts as the visual layer between the underlying analysis and the person exploring the data. Instead of presenting raw datasets, it communicates pollution patterns, source-related insights, and forecasting information through interactive visualizations.

  • Interactive pollution trend visualizations
  • AQI forecast information
  • Source-related pollution insights
  • Data-driven visual summaries for faster interpretation
05
The Outcome
What I Built

A data-driven system for understanding and forecasting Delhi-NCR air quality.

The final project combines data analysis, AQI forecasting, and dashboard development into a single experience. It transforms a large historical dataset into interactive insights while adding a forecasting layer that makes the analysis more forward-looking.
